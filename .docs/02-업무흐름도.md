## 신청자 문서 처리

```mermaid
flowchart TD
 A[공개 앱 진입] --> B[공용 applicant 안내 확인]
 B --> C[홈]
 C --> D{신청 방식}
 D -->|직접 작성| E[폼 입력·임시 저장]
 D -->|작성 완료 PDF| F[PDF 묶음 업로드]
 F --> G[UPLOADED로 대기]
 G --> H[사용자가 문서 검토 요청]
 H --> I[PDFBox 페이지 분리·사진 추출]
 I --> J[PaddleOCR 인식]
 J --> K{AI 보조 선택/활성}
 K -->|사용| L[OpenRouter Gemma 4 제안]
 K -->|미사용/실패| M[OCR 결과 직접 검토]
 L --> N[사용자 확인·수정]
 M --> N
 N --> O[신청에 반영·제출]
 E --> O
 O --> P[관리자 배정·담당자 검토]
 P --> Q{보완 필요?}
 Q -->|예| R[보완 요청·재제출]
 Q -->|아니오| S[결과 확정·조회]
 R --> P
```

기존 PNG/JPEG 직접 첨부 경로도 지원한다. `/demo`와 공개 SC-00 체험은 제공하지 않는다. `PREPARED` 결과 재생은 저장된 결과를 보여주며 실제 OCR 호출로 계산하지 않는다.

## 상태와 유지관리

업로드 직후 `UPLOADED`; 명시적 요청 후 `QUEUED`/`PROCESSING`; 분석 완료 `READY`; 신청 반영 `APPLIED`; 실패 `FAILED`. 공개 공용 계정 자료는 KST 매일 04시 초기화된다. content-addressed 파일은 참조 여부에 따라 재사용하거나 orphan 수거한다.
