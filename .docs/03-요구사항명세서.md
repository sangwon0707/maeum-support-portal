# 요구사항 명세서

> **현행 상태 기준 (2026-10-26):** 아래 요구사항 표는 설계 추적용이다. 현재 구현·부분검증·미검증 구분은 [구현 검증 결과](15-구현검증결과.md)를 확인한다. 공개 `/demo` 경로는 없고, 신청 PDF 검토 및 OCR 연동은 구현됐다. 성능/정확도 비교와 Oracle DB 호환성은 미검증이다. 초기 요구사항은 [archive/03-initial.md](archive/03-initial.md)에 보존한다.

## 1. 식별·우선순위

FR 기능 요구사항, NFR 비기능 요구사항, BR 업무 규칙, SC 화면, TC 수용 테스트. P0 핵심 / P1 차별화 / P2 후속 검증. 완료 기준은 수용 조건이며 현행 상태는 위 요약 및 15번 증거 문서가 기준이다. 설계 시점의 요구 문구는 초기 archive 사본과 비교한다.

## 3. 업무 규칙

| ID | 규칙 |
|---|---|
| BR-001 | 일반 계정은 workspace·program·owner 조합당 신청 1건. 개발용 applicant 계정은 제출 이후 새 회차를 허용하며 작성·보완 중이면 기존 건을 사용한다. 기존 제출본은 보존한다. 운영 공간과 데모 공간은 분리한다. |
| BR-002 | DRAFT만 일반 수정 가능. NEEDS_SUPPLEMENT는 요청된 필드·서류만 수정 가능. |
| BR-003 | 최초 제출은 opens_at ≤ now < closes_at, 보완은 now < due_at. 화면 시각은 Asia/Seoul. |
| BR-004 | 모든 상태 변경은 expectedVersion 비교와 이력 기록을 한 트랜잭션으로 처리한다. |
| BR-005 | 제출 revision은 불변이고 당시 첨부파일 ID도 함께 고정한다. |
| BR-006 | 선정·미선정은 UNDER_REVIEW에서만 가능, 확정 사유 필수. 확정 후 재개방은 범위 제외. |
| BR-007 | 신청 금액은 정수 원화 1원~10,000,000원. 소수·음수·상한 초과 거절. 가상 사업의 정책값이다. |
| BR-008 | 필수 서류는 사업자등록증·견적서 각 1종, 버전별 보존. PNG/JPEG 각 10MiB 이하. |
| BR-009 | 사업자번호는 숫자 10자리 형식 검사. 실제 등록 여부 조회·진위 검증으로 표현하지 않는다. |
| BR-010 | 데모 공간 만료는 생성 후 24시간, 세션당 활성 공간 1개·공간당 OCR 10회. 설계 기본값이며 설정 가능. |
| BR-011 | 공개 체험의 파일은 제공 fixture만 선택한다. 실제 업로드 UI는 인증 개발 모드에서 가상 자료로 검증한다. |
| BR-012 | OCR confidence는 제공 시에만 기록. 신뢰도 미제공은 미상이며 자동 승인 근거가 아니다. |

## 5. 미확정 사항

OCR/PDF 분석은 PaddleOCR·PDFBox 및 선택 OpenRouter/Gemma 4로 연동됐다. 외부 AI 공급 경로·계약·보유조건, 호스팅, 백업 보유·파기 조건은 미확정이다. 공개 공용 계정은 KST 매일 04시 초기화된다.

현재 구현·검증 범위는 [구현 검증 결과](15-구현검증결과.md)를 참고한다. 본문은 구현 전 설계 기준을 보존한다.

## 신청 업무 개편 요구사항 — 2026-10-23

- FR-021: 일반 신청자 회원가입, 비밀번호 해시 저장, 공개 가입의 업무 권한 부여 금지.
- FR-022: 빈 신청서 생성, 사업자·사업장·업태·종목·계획·신청금액·자부담 입력, 부분 임시저장, 최종 제출 시 필수 검증.
- FR-023: PNG/JPEG 직접 업로드, 예시 PNG 내려받기, 신청자가 선택할 때만 예시 정보 입력.
- FR-024: 확인값 저장과 신청서 반영 동작 분리, 현재 서류·소유권·작성 상태·신청 버전 검증.
- FR-025: 공고 대상·항목·제외·검토 기준·문의 정보 관리, 관리자 배정과 담당자 접수 업무 연결.

현재 수용 증거와 한계는 20번 문서에 기록한다.


## 공개 포트폴리오의 계정 입력 — 2026-10-26

공개 앱 진입은 공용 applicant 계정 안내 모달을 거친다. `/demo`는 제공하지 않는다. 상세 공개 화면과 경로는 현재 Controller 및 화면 정의를 기준으로 한다.

## LLM 문서 해석 — 2026-10-26

- LLM-001: 실제 문서 검토에서 인식 원문 전체를 한 번 전송하여 항목 후보·줄 번호·문서 분류 제안을 받는다.
- LLM-002: 원문에 존재하지 않는 후보와 잘못된 날짜·금액을 제외한다. 기존 값은 보존하고 검증된 누락값만 보완한다.
- LLM-003: 분류 제안과 기본 분류가 다르면 사용자 확인 대상으로 표시한다. 자동으로 문서 경계를 바꾸지 않는다.
- LLM-004: 실패·429·시간 초과에도 기본 인식 결과를 확인할 수 있어야 하며 실패를 성공으로 표시하지 않는다.
- LLM-005: 문서당 1회, 기본 6 RPM·동시 1건, 자동 재시도 금지, 429 대기시간과 호출 예약의 프로세스 간 공유를 적용한다.
