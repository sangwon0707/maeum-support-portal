# 현재 화면 정의

갱신일: 2026-10-26 · 초기 SC 화면 설계와 전체 목록은 [archive/04-initial.md](archive/04-initial.md)에 보존했다. 아래는 실제 제공 흐름 요약이며 정확한 라우트는 현재 Controller가 기준이다.

| 흐름 | 화면/기능 | 현재 동작 |
|---|---|---|
| 진입 | 홈 | 공용 applicant 계정 안내·확인 모달 후 진입 |
| 신청 | 신청 폼 | 신청자가 필드를 직접 입력하고 저장 |
| 첨부 | 문서 첨부 | PNG/JPEG 기존 첨부 또는 작성 완료 PDF 묶음 업로드 |
| 문서 검토 | 업로드 상태·검토 요청 | PDF 업로드 직후 `UPLOADED`; 사용자 요청 뒤 PDFBox/PaddleOCR와 선택 OpenRouter 분석 |
| 결과 확인 | 문서 검토 결과 | 추출값·신청값 대조, 사용자 수정 후 신청에 반영 |
| 업무 | 제출·배정·검토·보완 | 제출 후 관리자 직접 검토 또는 담당자 배정, 검토·보완·결과 조회 |
| 정책 | `/terms`, `/privacy` | 로그인 없이 열람 가능 |

`/demo`와 SC-00 공개 체험은 제공하지 않는다. `PREPARED` 사례는 저장된 결과의 재생이므로 실시간 OCR 화면으로 표시하지 않는다.

## 화면과 코드 위치

HTTP 진입은 `src/main/java/kr/co/maeum/support/controller/`, 입력 폼은 `dto/`, 화면에 전달하는 업무 데이터는 `model/`에서 관리한다. JSP는 `src/main/webapp/WEB-INF/views/`에 유지한다. 패키지 이동으로 URL·화면 ID·입력 항목을 변경하지 않았다.

## 관리자 접수 검토 진입

`/admin`의 접수 검토하기와 상단 접수 검토 메뉴는 `/staff/applications`로 연결한다. 관리자는 같은 공간 전체 신청 목록과 상세를 조회하고 배정 없이 처리한다. 담당자는 같은 화면에서 배정된 건만 조회·처리한다. 기존 공고 관리·배정·통계·감사 이력 메뉴는 유지한다.

로그인 화면은 왼쪽 사용자 테스트 계정, 오른쪽 관리자 테스트 계정을 같은 너비로 배치한다. 각 버튼은 해당 공개 계정만 입력하며 로그인과 공개 계정 안내 확인 절차는 그대로 유지한다.
