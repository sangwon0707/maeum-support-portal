# 검증 계획 및 요구사항 추적표

> **검증 상태 갱신 (2026-10-26):** 일부 공개 Oracle 앱에서 실제 PDFBox·PaddleOCR·OpenRouter 동작 증거를 확인했다. 이는 전체 TC 합격 매핑이나 운영/Oracle DB 호환성 증거가 아니다. 완료·부분 검증·미수행을 구분하며 전체 수용기준 달성으로 표시하지 않는다. 초기 계획은 [archive/06-initial.md](archive/06-initial.md).

## 1. 기능 수용 시나리오

아래 `미실행`은 이 TC 전체의 일괄 수용 판정이 없다는 의미다. 초기 구현 테스트 17개와 HTTP 점검 17개는 당시 수행 기록이며, 이후 회귀 수는 마지막 절과 15번 문서를 따른다. 이 초기 수치를 현재 전체 수로 보지 않으며 TC와 1:1로 대응한다고 간주하지 않는다. 15번 문서의 검증 항목을 함께 확인한다.

## 2. 핵심 통합 검증 절차

- TC-005: 정상 입력·필수 서류로 제출 → revision·첨부 연결·상태 이력 확인. 같은 키 재요청은 동일 revision, 다른 payload는 409. 마감 직전/동일 시각/이후 검증.
- TC-009: 담당자 보완 요청 → 신청자는 지정 항목만 변경 → 기한 내 재제출 → 기존 revision 불변. 기한 이후와 미지정 항목 변경은 차단.
- TC-010: 같은 version으로 두 담당 처리 요청 → 하나만 성공. 결과·상태·이력 불일치 없어야 함.
- TC-014: 두 세션에서 공간 생성 → 상대 신청·서류·OCR·역할 전환 접근 차단. 한 공간 재시작이 다른 공간에 영향 없음.
- TC-015: 공급자 모의 timeout/일시 오류/영구 오류·프로세스 중단 → 제한 재시도·lease 회수. 교체 전 서류의 늦은 결과 미사용. LIVE는 실제 엔진 증거 별도.

## 3. 예시 체험 fixture

| 코드 | 가상 입력 | 예상 결과 |
|---|---|---|
| NORMAL | 가상상점·신청금액 3,000,000원·서류 2종 | 불일치 없음·제출 가능 |
| MISMATCH | 신청 상호 가상상점 / OCR 상호 가상문구점 | 상호 불일치·확인 후 제출 |
| MISSING | 견적서 없음 | 제출 차단·SC-05로 수정 안내 |
| SUPPLEMENT | 견적서 재작성 요청·유효 보완 기한 | 지정 서류 교체·답변 후 새 revision |
| OCR_FAIL | 샘플 엔진 실패 응답 | 수동 확인으로 제출 가능 |

모든 이름·번호·문서는 가상이며 fixture 생성 시 테스트 문구를 이미지에 명시한다. 실행용 샘플 이미지는 FixtureImages에서 생성한다. 별도로 제작한 정상 사례 2건과 이미지형 PDF·페이지 PNG는 17번 문서를 따른다. 새 자료의 자동 체험 연결은 아직이다.

## 4. 비기능 검증

NFR-001/002: 권한·CSRF·위장파일·경로 입력·HTML 입력·로그 원문 노출 확인.
NFR-003: 브라우저 390/900/1440px, 키보드·확대·오류 포커스. 와이어프레임 확인과 제품 검증을 구분.
NFR-004: 10,000건·동시 10사용자 목록/집계 측정. 장비·DB 버전·예열·횟수·p95·실행계획·정합성 기록.
NFR-005/006: 작업 중 프로세스 종료, WAR 재배포, DB·파일 복원.
NFR-007~010: 추적표 누락·출처·MariaDB 실행·유지보수 사례 확인.

## 5. 증거 기록 형식

날짜 / commit / 환경 / 입력·재현 절차 / 예상 / 실제 / 로그·스크린샷 / 판정 / 제한. 로컬 업무 검증, 실제 OCR, 운영 배포는 각각 기록한다. 문서 작성·정적 와이어프레임 검토를 서비스 테스트 통과로 표시하지 않는다.

## 계층별 패키지 정리 후 회귀 근거

현재 테스트도 `controller`, `service`, `service/policy`, `mapper`, `storage`, `integration/ocr` 역할에 맞춰 배치했다. 실제 MariaDB Java 회귀 67개·PDF 모듈 3개·Python 33개와 로컬 HTTP 신청·문서 검토·제출·배정 접근을 확인했다. 이 결과는 기존 TC 전체의 일괄 합격 판정과 구분하며 상세 실행 범위는 [15번](15-구현검증결과.md)의 MVC 계층 회귀 절을 따른다.

## 관리자 직접 검토 회귀

관리자 미배정 접수의 선정·미선정, 보완 요청과 신청자 재제출, 타 공간 관리자 차단, 신청자·미배정 담당자 차단과 배정 후 담당자 허용, SecurityFilterChain의 검토 URL 역할 검사를 검증한다. 관련 구현은 WorkflowIntegrationTest의 관리자 직접 검토 5개 사례다.
