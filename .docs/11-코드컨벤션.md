# 코드 컨벤션

## 기본 원칙

MVC 계층별 패키지로 웹·업무·저장 책임을 분리한다. `controller`는 HTTP, `service`는 업무·트랜잭션, `mapper`는 MyBatis 인터페이스, `dto`는 입출력 객체, `model`은 업무 데이터 객체를 둔다. 순수 업무 규칙은 `service.policy`에서 관리한다. 구현체가 하나인 모든 서비스에 형식적인 인터페이스를 만들지 않고, 교체 가능성이 있는 저장소·OCR에만 경계를 둔다. 의존성은 생성자로 주입하며 Lombok·리플렉션 기반 필드 주입은 사용하지 않는다.

## 이름

패키지는 소문자, 클래스는 PascalCase, 메서드·변수는 camelCase, 상수·상태 코드는 UPPER_SNAKE_CASE. `data`, `info`, `temp`, `doProcess`처럼 뜻이 불분명한 이름 대신 `application`, `supplementRequest`, `submitApplication`처럼 업무 명칭을 쓴다. 컬렉션은 복수형, boolean은 is/has/can으로 의미를 드러낸다. 물리 컬럼은 snake_case, Java 속성은 camelCase로 매핑한다.

Controller: HTTP 바인딩·검증 결과·리다이렉트. Service: 권한·유스케이스·트랜잭션. Policy: 순수한 상태·입력 규칙. Mapper: SQL, 저장 계층. Request/Form: 입력 전용 객체. View: 출력 모델. Entity: DB 한 행. 페이지는 1부터, 정렬 동률 기준을 명시한다.

## 형식·예외·주석

Java 4칸, XML/JSP/JS/CSS 2칸, UTF-8, LF. 중괄호 생략 금지. wildcard import 지양. 메서드는 하나의 업무 책임을 수행하며 반복은 의미 있는 메서드로 추출한다. 업무 예외는 코드·HTTP 상태·한글 메시지로 관리하고 예외를 삼키지 않는다. 로그에 문서 원문·비밀번호·OCR 원문을 남기지 않는다.

공개 API는 의도와 계약을 설명한다. 한글 주석은 상태 변경 원자성·파일/DB 보상·샘플 엔진 한계처럼 코드로 드러나지 않는 이유를 적는다. 자명한 getter나 코드 한 줄마다 주석을 붙이지 않는다. `TODO`에는 범위·미구현 이유를 적고 구현 완료처럼 보이지 않게 한다.

## 데이터·보안·테스트

조회와 변경 모두 서버에서 역할·공간·소유권·배정을 확인한다. 금액은 BigDecimal/DECIMAL, 시각은 UTC 저장·한국 시간 표시. Service 트랜잭션 안에서 상태·revision·이력을 함께 저장한다. SQL은 파라미터 바인딩하고 사용자 입력으로 정렬 SQL을 조립하지 않는다. JSP는 c:out으로 출력한다.

테스트 이름은 `행동_조건_예상결과`를 뜻하는 영어 snake_case로 작성하고 설명은 한글 DisplayName으로 단다. 업무 경계·잘못된 권한·동시 제출·보완·파일 검증을 우선한다. 가짜 DB로 실제 MariaDB 검증을 대신하지 않는다.

## 자동 포맷

Java는 google-java-format 1.28.0 AOSP(4칸)로 고정했다. `./scripts/format.sh`로 적용하고 `--check`로 검사한다. JSP는 구조별 줄바꿈과 2칸 들여쓰기로 정리하고 공통 레이아웃·CSRF·상태 태그를 재사용한다.

## 패키지 배치

| 패키지 | 책임 |
| --- | --- |
| controller | URL·요청 바인딩·JSP 연결·공통 HTTP 오류 처리 |
| service | 신청·문서·공고·검토·자료 정리 업무와 트랜잭션 |
| service.policy | 입력·업무 상태·문서 분류·검증 규칙 |
| mapper | MyBatis 인터페이스. SQL은 resources/mapper XML |
| dto | 요청 폼·처리 결과 전달 객체 |
| model | 신청·공고·첨부·계정·작업·보완 데이터 |
| config | Spring·DB·Security·환경 설정·로컬 실행기 |
| security | 로그인 주체와 역할·소유권 접근 검사 |
| integration.ocr | 내부 OCR API 호출·공급자 어댑터·응답 경계 |
| scheduler | DB 대기 작업 실행·사전 결과 진행·정기 정리 호출 |
| storage | 비공개 파일·내용 주소 저장·파일 생성·수거 잠금 |
| common | 공통 예외·JSON·화면 형식 변환 |

기능은 클래스 접두어로 구분한다. 예를 들어 IntakeController → IntakeService → IntakeMapper → IntakeMapper.xml 순서로 문서 검토를 따라간다. 업무 규칙을 Controller나 스케줄러에 옮기지 않으며, 구조 정리만으로 Service 인터페이스·Impl을 일괄 추가하지 않는다.
