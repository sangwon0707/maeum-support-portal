# 유지보수 사례 — 한글 폼 인코딩과 초기화 순서

## 발견한 증상

브라우저로 가상 신청서를 저장한 뒤 OCR 대조 화면을 열었을 때, 신청서의 한글 상호가 깨지고 정상 샘플 OCR과 불일치로 표시되었다. Service를 직접 호출하는 통합 테스트에서는 재현되지 않았다.

## 원인과 수정

CSRF 필터가 요청 파라미터를 읽은 다음 DispatcherServlet 쪽 CharacterEncodingFilter가 실행되어 인코딩 설정이 늦었다. UTF-8 설정을 보안 필터 앞에 두고 web.xml에도 요청·응답 기본 인코딩을 지정했다.

외부 Tomcat 검증에서는 초기화 순서가 달라 인코딩 필터 중복 등록도 발견했다. DispatcherServlet 측 중복 필터를 제거해 SecurityInitializer에서 한 번만 등록하도록 수정했다. 내장 서버만 확인하면 배포 초기화 문제를 놓칠 수 있음을 확인했다.

## 회귀 검증

scripts/http-smoke.py에서 실제 HTTP·세션·CSRF를 통과하여 한글 개선 계획 저장→재조회, 한글 결과 사유 확정→신청자 조회, 제출 당시 스냅샷 조회를 점검한다. 가상 데이터로 개발 중 발견한 결함이며 고객 운영 장애 사례가 아니다. 최종 결과는 구현 검증 결과 문서를 따른다.
