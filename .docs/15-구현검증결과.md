# 구현 검증 결과

갱신일: 2026-10-26. 과거 단계별 수치는 [이전 검증 기록](archive/15-previous.md)에 보존했다. 아래 결과는 실행 범위별로 구분하며 현재 변경을 다시 전부 실행했다는 뜻은 아니다.

## 기능 전환 회귀

PDFBox 전환 당시 Java/MariaDB 업무 66개·Java PDF 모듈 3개·Python 33개, 총 102개 테스트를 통과했다. 권한·소유권·상태·제출·보완·공유 파일·저장 상한과 PDF 계약을 검증했다. 원문 추출·회전·CropBox·분할·인증·입력 제한·AI 원문 근거를 포함한다.

그 뒤 추가한 잠금 회귀 JUnit 사례는 컴파일을 확인했으며 전체 103개가 실행됐다고 표시하지 않는다. 실제 MariaDB 별도 스키마에서 데모 행 잠금과 만료 수거를 동시에 실행해 만료된 LIVE만 실패하고 데모·유효 작업을 보존하는 것을 확인했다. 상세는 [33번](33-PDFBox전환및회귀검증.md)을 따른다.

## 실제 엔진·외부 공급자

텍스트 PDF 전체 앱 처리 시간과 이미지 기반 1쪽 OCR 시간을 혼동하지 않는다. 공개 사이트의 이번 확인은 최종 제출·담당자 배정까지 다시 실행한 전체 업무 E2E가 아니며 해당 범위는 로컬 실행 증거다.

## 화면·업무 흐름

초기 Java/HTTP 업무 검증, 직접 작성·증빙 OCR, 문서 전체 검토 브라우저 검증은 서로 다른 실행 기록이다. 최신 문서 검토는 한 묶음 업로드·원본 대기·명시 요청·원본/분할/사진 탭·신청 내용 수정·반영을 확인했다. `/demo`는 404이며 공개 시나리오 선택 화면이 아니다.

현재 유지하는 대표 캡처는 루트 README의 `.docs/images/portfolio/` 이미지 5개다. 과거 `output/`·`.local/` 증거는 Git에 포함하지 않으며 정리된 캡처를 현재 보관 중이라고 쓰지 않는다. 기존 촬영·테스트 결과는 당시 기록으로 보존한다.

## 배포·보안 경계

Oracle의 앱·DB·OCR 컨테이너, Caddy·Cloudflare HTTPS, Fail2ban SSH 차단·해제를 확인했다. DB·OCR 외부 포트 및 공급자 키 공개를 허용하는 구성이 아니다. 공개 계정은 실제 DB에 저장되고 다른 방문자와 공유되므로 실제 개인정보를 입력하지 않도록 안내한다. 일일 초기화·파일 수거는 구현됐지만 실제 04시 운영 실행 관찰·완전한 백업 복원·전체 침투 테스트를 통과한 것으로 표시하지 않는다.

## 이번 문서·공개 범위 정비

라이선스 고지·파일 제외·정적 자산·문서의 현황을 맞췄다. 문서 링크와 공개 대상·고지·CSS 참조 검사 및 Maven 리소스 복사를 확인한다. 이 작업을 전체 기능 회귀 재실행이나 서버 재배포로 표시하지 않는다. 현재 로컬 정비와 기존 운영 버전을 구분한다.

## MVC 계층 패키지 리팩터링 회귀 — 2026-10-26

Java 본체 82개·테스트 17개를 계층별로 재배치한 뒤 clean test-compile을 통과했다. 실제 MariaDB를 사용하는 Java 회귀 67개, PDFBox 모듈 3개, Python 33개, 총 103개가 실패·오류 없이 통과했다. 이 수치에는 앞 절에서 컴파일만 확인했던 잠금 회귀 사례의 실제 실행도 포함한다. WAR 패키징과 Java 포맷 검사도 통과했다.

이전 구조와 비교해 패키지·import·한정 클래스명을 제외한 업무 메서드 본문은 같았다. 의도한 설정 변경은 MapperConfigurer 스캔을 `kr.co.maeum.support.mapper`로 좁힌 것이다. Mapper XML은 namespace와 Java resultType만 바뀌었고 SQL 문장·마이그레이션은 변경하지 않았다.

로컬 실제 Tomcat HTTP 검증은 공개 화면 9개와 인증 후 나의 신청·마이페이지를 포함한다. 로그인 → 가상 스캔 PDF 업로드 → UPLOADED 유지 → PREPARED 요청 → READY → 결과 파일 13개 조회 → 신청 반영(APPLIED) → 최종 제출 → 관리자 배정까지 통과했다. 담당자는 배정 전 문서 검토 접근 403, 배정 후 200이었다. 회원가입 POST 405, 삭제한 `/demo` 404도 유지했다.

검사 로그·생성 신청은 로컬 검증 자료이며 `.local/`에 관리한다. 문서 검토 데모의 사전 결과와 공급자의 새 실행을 혼동하지 않는다. 이번 검증 결과는 구조 변경 후의 컴파일·실제 DB·HTTP 계약 근거다.

## 관리자 직접 검토와 계정 선택

Java/MariaDB 72개·PDF 모듈 3개·Python 33개, 총 108개 테스트가 통과했다. 추가한 5개 회귀 사례는 관리자 직접 선정/미선정, 보완·재제출, 공간 격리, 신청자와 미배정 담당자 차단, 실제 SecurityFilterChain의 검토 URL 접근을 확인한다.

로컬 Tomcat HTTP에서 가상 PDF 업로드 → 검토 데모 → 원본/분할 파일 13개 조회 → 신청 반영·제출 → 관리자 미배정 검토 → 계획 보완 요청 → 신청자 수정·재제출 → 관리자 선정 → 신청자 결과 조회를 통과했다. 새 외부 OCR/LLM 호출을 수행한 검증과 구분한다. 로그인 화면의 사용자·관리자 버튼은 실제 브라우저에서 각 계정 입력과 좌우 배치를 확인했다.

공개 HTTPS에서도 가상 PDF 업로드와 검토 데모, 분할 파일 13개 조회, 신청 반영·제출, 관리자 미배정 검토·계획 보완 요청, 신청자 수정·재제출, 관리자 선정과 신청자 결과 조회를 통과했다. 신청자 검토 접근과 미배정 담당자 접근은 403을 유지했다. 실제 브라우저에서 사용자·관리자 계정 입력 버튼, 안내 확인 후 관리자 로그인·홈 이동과 접수 검토 메뉴 진입을 확인했다. 이 검증은 기존 OCR 결과를 사용하는 데모 흐름이며 새 OCR/LLM 공급자 호출 증거로 사용하지 않는다.

## 역할별 안내·공통 확인 모달 검증

로컬 실제 브라우저에서 로그인 전 금색/핑크색 테두리 두 개, 계정 선택 후 안내 한 개, 관리자 로그인 후 접수 검토 메뉴·접수 상세·검토 시작·결과 사유·확인 모달로 이어지는 안내를 확인했다. 결과 확정 모달의 취소·ESC에서는 POST가 없고, 최종 확인에서는 decision POST가 한 번만 발생해 결과가 확정됐다. 브라우저 기본 dialog 호출은 없었다. 웹 소스 전체의 alert/confirm/prompt 호출도 0건이다. Java 업무 권한·DB·OCR 변경 없이 JSP·CSS·JavaScript를 WAR로 패키징했다.

공개 HTTPS의 실제 브라우저에서도 두 계정 안내 → 관리자 핑크색 전환 → 로그인 → 접수 검토 → 결과 선택·사유·검토 확인 → 공통 확인 모달 → 결과 확정을 통과했다. 취소와 ESC에서는 decision POST 0회, 최종 확인에서는 1회, 기본 브라우저 dialog 호출은 0회였다. 앱 health 200과 healthy 상태를 확인했다.

## 확정 사유 자동 입력 검증

로컬 실제 브라우저에서 선정 문구 자동 입력, 미선정 전환 시 자동 문구 갱신, 직접 수정한 사유 보존, 버튼으로 재입력, 자동 입력 시 POST 0회, 최종 모달의 동일 사유 표시, 취소 후 미제출과 확인 후 단일 POST·실제 사유 저장을 확인했다. Java 업무·DB·OCR 변경은 없으며 웹 자원을 WAR로 패키징했다.

자동 입력 버튼 추가 후에도 검토 체크를 마치면 핑크색 안내가 보조 버튼이 아닌 실제 결과 확정 제출 버튼으로 이동하는 것을 브라우저에서 확인했다.

공개 HTTPS 브라우저에서도 선정/미선정 자동 문구, 직접 수정한 사유 보존, 자동 입력 시 미제출, 확인 모달의 사유 표시, 취소 후 미제출과 최종 확인 POST 1회·사유 저장을 확인했다. 검토 체크 후 안내는 실제 결과 확정 제출 버튼으로 이동했다.
