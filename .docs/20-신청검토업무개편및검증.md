# 신청·검토 업무 개편 및 검증

갱신일: 2026-10-26 · 현재 Oracle 앱 흐름과 검증 경계를 기술한다. 초기 개편안은 [archive/20-initial.md](archive/20-initial.md).

## 현재 신청·검토 흐름

공개 앱 진입 시 공용 applicant 계정 확인 모달을 거쳐 홈에 진입한다. `/demo`는 제거돼 제공되지 않는다. 신청자는 직접 폼을 작성하거나 작성 완료 PDF 한 묶음을 올릴 수 있다. 업로드 직후 상태는 `UPLOADED`이며 사용자가 문서 검토를 눌러야 PDFBox 분할·사진 추출과 PaddleOCR가 시작된다. OpenRouter/Gemma 4 보조는 선택적으로 실행되며, 신청자는 추출 결과를 확인·수정한 뒤 반영하고 제출한다. 기존 PNG/JPEG 첨부 방식도 유지된다. 제출 후 배정·검토·보완 흐름은 일반 업무 경로다.

공용 계정 데이터는 KST 매일 04시 초기화된다. 스케줄러는 5분 간격으로 유지관리 작업을 확인하고, 생성한 content-addressed 파일은 참조 여부에 따라 재사용·orphan 수거한다. 이용자 간 공유 계정이므로 입력 자료는 다른 방문자에게 노출될 수 있다는 사용 경계를 명시한다.

## 검증 증거와 한계

공개 Oracle 앱에서 텍스트 PDF 6쪽 결과 `READY` 103.29초, 스캔 PDF 1쪽 57줄 111.49초, 준비 결과 재생 `READY` 59.11초를 확인했다. 준비 결과는 실시간 OCR 증거가 아니다. 이는 OCR 경로의 사례 증거이며 전체 신청-배정-보완 E2E, 모델 정확도 순위, Oracle DB 호환성 또는 법률 준수 완료를 뜻하지 않는다. 자세한 최신 테스트 범위는 [구현 검증 결과](15-구현검증결과.md)를 따른다.
