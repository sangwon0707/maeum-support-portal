# 서비스 디자인 규칙

작성일: 2026-10-25. 적용 브랜치: `feat/content-design-refresh`.

## 방향과 근거

마음이음은 소상공인이 사업을 찾고 신청·서류·보완·결과를 관리하는 업무 서비스다. 현재 등록 공고가 적은 환경에서 검색을 과도하게 확대하지 않는다. 첫 화면은 실제 공고의 내용과 신청 진입을 우선하며, 장식용 표어와 그림으로 대부분의 화면을 채우지 않는다. 마음이음 A안 로고를 현재 헤더에 적용했다. 아래 토큰·레이아웃은 서비스 규칙이며 뒤의 날짜별 검증 기록은 당시 화면에 대한 기록이다.

[정부 사이트 10곳 조사](references/government-sites/README.md)에서 청주시 통합예약의 검색·분류·조회와 대전 동구 통합예약의 유형별 목록·상태·마이페이지 구성을 우선 참고한다. 익산의 주요 서비스 바로가기, 보건복지상담센터의 업무별 진입 구분을 보조로 참고한다. 레퍼런스의 색상·이미지·기관 로고를 복제하지 않는다.

## 화면 구조

1. 헤더: 서비스 정체성·로그인·주 메뉴. 공식 정부 누리집 문구와 국장은 사용하지 않는다. 포트폴리오·가상정보 안내는 상단에 유지한다.
2. 메인: 페이지 제목·나의 신청 → 작은 검색 도구 → 실제 공고와 금액·기간·신청 진입 → 대상·지원 내용·제외·검토 기준 → 필수 서류 → 처리 절차. 반복 안내 카드와 메인 FAQ는 사용하지 않는다. 검색은 기존 GET 파라미터 `keyword`, `state`를 사용한다.
3. 공고: 상태·온라인접수·제목·대상·금액·기간·상세 진입을 동일 순서로 표시한다. 조회 결과의 첫 공고를 전체 폭으로 소개하고 나머지는 간결한 목록으로 제공한다. 조회 결과가 없으면 빈 결과와 전체 목록 복귀를 제공한다. 첫 공고를 추천·인기 공고로 표현하지 않는다. 닫힌 공고를 녹색 접수 중과 같은 의미색으로 표시하지 않는다.
4. 상세: 안내·대상·지원 내용·제외·기준·서류·문의·절차를 구분하고, 접수 요약과 신청 행동을 우측에 둔다. 긴 화면의 목차는 실제 제목 위치로 연결한다.
5. 작성·업로드·OCR: 공통 제목·단계·본문 패널을 유지한다. 장식 이미지와 마케팅 문구를 입력 영역에 넣지 않는다. 오류·보완·직접 확인은 기존 업무 규칙대로 표시한다.
6. 이용 안내: 준비 서류와 입력 방법, 제출 이후 절차를 구획화하고 관련 위치로 바로 이동할 수 있게 한다.

## 이미지와 콘텐츠

기본 이미지 생성 도구로 소상공인 가게와 신청 서류를 표현하는 원본 일러스트 1개를 제작한다. 용도는 메인 공고 소개의 보조 장식이다. 읽기를 방해하지 않도록 모바일에서는 숨기며 핵심 정보는 이미지에 의존하지 않는다. 이미지 안에 공고 제목·기간·핵심 조건을 넣지 않으며 필요한 텍스트는 HTML로 제공한다. 이미지 아래에 AI 제작 안내를 표시하고 생성 프롬프트·원본 출처를 `.ref`에 기록한다. 사진·실제 수혜자·지원 실적으로 표현하지 않는다.

임의의 사업·공지·모집 수·선정 실적·처리 기간을 만들지 않는다. 실제 등록 데이터와 현재 구현된 기능 설명만 사용한다. 문서 자동 채움·OCR·AI는 실제 동작 범위를 넘겨 홍보하지 않는다.

## 접근성과 반응형

검색·주요 행동은 키보드로 도달 가능하게 하고 기존 포커스 테두리를 유지한다. 상태는 색 외에 문구로 구분한다. 메인에서 중복 FAQ는 제거하고 상세 안내로 연결한다. 가로 넘침을 만들지 않는다. 800px 이하 공고·접수 요약과 상세를 한 열로 전환하고 640px 이하 조건·서류·절차를 재배치한다. 입력 컨트롤의 KRDS 최소 높이와 라벨은 유지한다. 이미지가 로딩되지 않아도 검색과 신청 흐름은 사용할 수 있다.

## 검증 범위

빌드와 공개 경로, 데스크톱·모바일 실제 렌더링, 검색 결과·빈 결과·목차·로그인 진입을 검증한다. 권한·상태·SQL은 변경하지 않는다. 이번 UI 검증을 실제 OCR 공급자 재검증이나 배포 증거로 표현하지 않는다.

## 2차 재구성 — 2026-10-25

앞선 1차 화면 검증은 동작에 대한 기록이며 사용자가 디자인을 승인했다는 의미가 아니다. 반복 안내와 큰 검색 상자를 줄이고 실제 사업 정보가 먼저 보이도록 구조를 바꾼다.

- 헤더: `m·` 임의 로고를 제거하고 한글 서비스명으로 정리했다. 넓은 화면에서는 메뉴를 같은 줄에 배치한다.
- 공고: 실제 등록 제목·본문·금액·기간을 출력한다. 원본 데이터와 검색 계약은 바꾸지 않는다.
- 정보: 대상·지원 내용·제외·검토 기준은 관리자 등록 값을 표시한다. 없는 사업·실적·공지·기한을 만들지 않는다.
- 표현: 공고 소개와 진한 접수 요약, 선으로 나눈 조건 설명, 서류 목록, 단계 연결선으로 섹션의 역할을 구분한다. 일반 패널을 같은 모양으로 반복하지 않는다.
- 아이콘: 사용자·첨부·다운로드·안내는 프로젝트에 보존된 공식 KRDS 아이콘을 참조한다. 문자 기호로 아이콘을 대신하지 않는다. 화살표·검색은 단순 CSS 도형이다.
- 변경 범위: JSP·CSS·공통 헤더·푸터. Controller·Service·Policy·Mapper·권한·DB·상태 전이는 변경하지 않았다.

## 이미지 시안의 실제 서비스 반영 — 2026-10-25

별도 정적 시안에만 있던 거리 비주얼·안내 그래픽을 실제 `/`·`/programs` JSP에도 적용한다. 메인 상단에 큰 거리 이미지와 신청 진입을 배치하고, 네 개 업무 바로가기에 생성 아이콘을 연결한다. 등록 공고는 고정 공고키에 따라 서로 다른 현황 예시 이미지를 표시한다. 공통 JSP 태그에서 이미지 대응을 관리하고 새 관리자 공고는 일반 거리 이미지로 대체한다. 사업별 사진은 지원 실적이 아닌 AI 예시로 표시한다.

공고 목록의 6개 이미지, 서류 준비 그래픽, 네 단계 안내 이미지까지 사용한다. 동일한 카드만 반복하지 않도록 첫 공고는 사진·본문·접수 요약을 나누고 나머지는 사진 카드로 제공한다. 기존 검색·공고 상세·기간·한도·신청 진입은 DB 조회와 기존 경로를 유지한다. 앞 절의 모바일 이미지 숨김 기준은 이번 메인 비주얼에는 적용하지 않으며 모바일에서도 이미지를 노출한다.

생성 PNG 원본은 보존하고 `scripts/prepare-portal-images.py`에서 WebP 전송본을 만든다. `cwebp` 품질 82로 포맷만 변환하며 원본 화면 내용은 바꾸지 않는다. 안내 아이콘과 공고 사진은 지연 로딩하고 첫 거리 이미지는 우선 로딩한다. 작은 조작 아이콘은 KRDS 원본을 유지한다. CSS 버전으로 이전 테마 캐시를 갱신한다.
