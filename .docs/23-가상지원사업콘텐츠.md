# 가상 지원사업 콘텐츠

작성일: 2026-10-25. 실제 정부 사업을 수집·대행하는 목록이 아니라 포트폴리오에서 신청과 검토를 확인할 수 있는 가상 공고다. 실제 지원금은 지급하지 않는다.

## 사업별 차이

기존 환경개선 1개에 아래 5개를 추가해 기본 개발 환경에 총 6개를 제공한다. 각 사업은 본문·대상·지원 항목·제외·검토 기준·한도·접수 기간이 다르다.

| 사업 | 지원 한도 | 계획·견적서에서 확인할 내용 | 제외 예시 |
| --- | ---: | --- | --- |
| 매장 환경개선 | 1,000만원 | 간판·조명·배선 개선 필요성과 항목별 견적 | 이미 완료한 공사 |
| 디지털 매장 전환 | 500만원 | 주문·재고 업무 문제, 장비 모델·설정·교육비, 장애 대응 | 정기 구독료·통신비·결제 수수료 |
| 에너지 절감 설비 전환 | 700만원 | 기존 설비, 교체 규격·수량, 절감 예상 근거, 설치·처리비 | 요금·연료비·개인용 기기 |
| 모두를 위한 매장 이용환경 개선 | 400만원 | 출입·동선 불편, 현재 치수와 설치 규격, 시공 권한 | 무관한 고급 인테리어·무단 공용 공간 공사 |
| 온라인 판로 준비 | 300만원 | 촬영·페이지·영상 수량, 납품 파일, 수정 횟수와 이용 권리 | 광고 집행비·플랫폼 수수료·재고 매입 |
| 점포 안전·위생 개선 | 250만원 | 환기·바닥·급배수 현황, 공사 구역과 자재·시공비, 영업 운영 계획 | 정기 청소·소독·소모품 |

가격과 조건은 가상 공고의 설계값이며 실제 사업의 근거·지원 자격·효율 등급·인증을 보증하지 않는다. 세부 본문은 [추가 공고 원본](../src/main/resources/fixtures/programs/additional-programs.json)을 따른다. 실제 운영 중 관리자가 수정하면 DB의 공고가 기준이다.

## 구현 범위

필수 파일 유형은 현재 처리할 수 있는 사업자등록증과 항목별 견적서 두 가지로 공통이다. 대신 각 사업 본문에서 계획과 견적에 포함할 정보를 다르게 안내한다. 추가 증명서 업로드·실제 자격 조회·구매·지급 기능이 있는 것처럼 설명하지 않는다.

`LOCAL_SEED=true`에서 초기화하며 기존 환경개선 공고·신청·파일은 보존한다. 신규 공고는 V5의 고정 `seed_key`로 식별해 재시작해도 중복 생성하지 않고 관리자 수정값·기존 접수 기간을 덮어쓰지 않는다. 기간은 최초 생성 시점을 기준으로 잡고 이후 자동 연장하지 않는다. 운영에서는 `LOCAL_SEED=false`를 사용하고 관리자 화면에서 실제 공개할 공고를 관리한다.

실제 사이트는 DB에 등록된 공고를 출력하고, 8098번 이미지 시안은 같은 콘텐츠 원본을 이용한 정적 검토 화면이다. 두 화면을 실시간 동기화한 API는 추가하지 않았다.

## 검증·대응 샘플

2026-10-25 로컬 MariaDB에서 중복 초기화·관리자 수정 보존을 검증했다. 실제 서비스 공고 6건과 사업별 본문·한도·서류 안내를 확인했다. 최종 Java 테스트는 40개 통과했다. 새 사업 5개에 대응하는 신청서·사업계획·예산·현황 사진·사업자등록증·견적서는 [사업별 신청 샘플 및 검증](24-사업별신청샘플및검증.md)을 따른다.
