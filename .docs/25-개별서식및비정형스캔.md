작성일: 2026-10-25. 24번의 공통 프레임을 사용한 첫 예시는 보존하고, 사업마다 표 구조·제목 배치·항목·사진 배치를 달리한 추가 예시를 작성했다.

## 서식별 차이

| 사업 | 신청서·계획의 구성 | 현황 자료 구성 |
| --- | --- | --- |
| 디지털 전환 | 왼쪽 정렬 제목, 도입 전후 업무 비교, 기능·장비·교육 명세 | 큰 업무 공간 사진과 주문·재고·직원 사용 연결표 |
| 에너지 절감 | 에너지 개선 문서 제목 띠, 기존·교체 설비 대조, 소비전력·시간 확인 계획 | 설비 사진과 제품 사양 확인 메모를 나란히 배치 |
| 이용환경 개선 | 이중 상단선, 위치별 불편·치수·허가·예정 작업, 세로 사업비 표 | 출입구 사진 옆 치수·설치 권한 조사표 |
| 온라인 판로 | 제작 의뢰서 구성, 오른쪽 설명, 과업·납품 규격·수량·수정·권리 조건 | 상품 촬영 환경 사진과 산출물별 확인 항목 |
| 안전·위생 | 현장관리 제목 박스, 작업 구역별 점검·공사 범위·분리 조치 | 작업 공간 사진과 조리 후드·바닥·급배수 점검 메모 |

각 문서는 6쪽이다. 1 신청서, 2 사업별 계획, 3 산출·일정, 4 현황, 5 가상 사업자등록증, 6 견적서 순서로 유지한다. 사업자등록증의 공통 대조 항목과 예산 산술 규칙은 공통이며 제목·표·현황 배치는 분야별로 구분한다. 기존 정답 JSON의 상호·대표자·금액·품목을 바꾸지 않는다. 확인하지 않은 설비 소비전력·치수·인증·시공 결과를 사실처럼 채우지 않는다.

## 제작 결과

- 개별 서식 PDF 5개와 비정형 스캔 PDF 5개: `output/pdf/사업별신청예시-개별서식/`
- 개별 서식 페이지 PNG 30장: `output/images/사업별신청예시-개별서식/`
- 최종 img2img 편집 PNG 30장: `output/images/사업별신청예시-비정형스캔/`
- 입력·편집 프롬프트·출력 경로·검토 상태·SHA256: `.ref/document-scans/편집작업기록.json`
- 비교 페이지: `http://127.0.0.1:8098/distinct-samples.html`

기본 제공 이미지 생성 도구의 img2img로 페이지마다 개별 편집했다. 좌우 기울기, 약한 원근 차이, 종이 질감, 스캐너 여백, 가장자리 그림자와 노출 차이를 요청했다. 기존 원본에 단순 회전 필터만 적용한 작업이 아니다. 최종본 30장에 대해 30회 편집했고 이용환경 개선의 상호 대조를 위해 3장을 추가 재편집했다. 최종본은 최신 결과만 PDF에 넣으며 이전 편집본은 비교 출력과 분리한다. 위아래 빨간 가상 안내는 유지한다.

모든 스캔 이미지는 AI로 만든 가상 편집물이다. 실제 스캔·사진·인쇄 결과가 아니다. 생성 모델은 작은 글자나 사진 세부를 재해석할 수 있으므로 데이터 정답은 개별 서식 원본과 정답 JSON이다. AI 편집본을 글자까지 동일한 정답 데이터로 간주하지 않는다.

## 재생성·PDF 합성

```bash
.tools/documents-venv/bin/python scripts/build-distinct-program-samples.py
.tools/documents-venv/bin/python scripts/build-generated-scan-pdfs.py
python3 scripts/build-distinct-sample-gallery.py
```

첫 명령은 정답 JSON·사진에서 새로운 원본 PDF와 PNG를 생성한다. 이미지 편집은 기본 제공 도구로 수행하므로 CLI 명령만으로 재현되지 않는다. 편집 결과를 프로젝트에 복사하고 작업 기록의 출력 해시·검토 상태를 갱신해야 두 번째 명령을 실행할 수 있다. 생성은 확률적이므로 같은 프롬프트라도 같은 결과를 보장하지 않는다. 입력을 다시 작성하면 기존 편집본을 재사용하기 전에 입력 해시와 내용을 대조한다.

PDF 합성기는 검토 상태·해시·이미지 해상도·쪽수를 확인하며 편집 PNG 자체를 추가 변형하지 않는다. 페이지 비율을 보존해 A4에 넣고 텍스트 레이어를 추가하지 않는다. 갤러리는 정적 검토 자료이며 8098번 로컬 정적 서버가 필요하다. 기존 사이트의 다운로드용 사업자등록증·견적서 PNG는 이번 작업에서 교체하지 않았다.

## 검증 결과와 한계

| 검증 | 결과 |

| 로컬 보조 OCR | Apple Vision으로 30쪽의 원본 PDF 금액 표기와 편집본 인식값 대조. 금액 모두 일치. 이용환경 개선 1·5·6쪽에서 상호의 `퉁`을 `통`으로 읽는 등 일부 한글 후보 차이 발생. `편집본내용대조.json` |

보조 OCR 대조는 편집 검토용이며 서비스 PaddleOCR·NIM·OpenRouter 검증이나 문자 단위 인식률 실험이 아니다. OCR 오독과 이미지 생성 과정의 글자 변화는 이 검토만으로 모두 구분할 수 없으므로 완전한 글자 보존·인식률을 주장하지 않는다. 정답 대조·정확도 실험에서는 원본 PDF/JSON을 정답으로 고정하고 생성 편집본은 별도 변형 자료로 취급한다.

이번 변경은 문서·제작 스크립트·별도 검토 갤러리 범위다. 서비스 권한·상태·트랜잭션·DB 스키마는 변경하지 않았다. 당시에는 커밋·푸시·배포를 수행하지 않았다.
