> 기록 범위: 아래 날짜별 제작·촬영·검증은 당시 상태의 기록이다. 현재 공개 문서 검토·배포는 29·31~33번 문서를 따른다. `output/` 증거 파일은 정리되거나 새 체크아웃에 없을 수 있다.


촬영일: 2026-10-25. 로컬 Java 서버와 MariaDB에서 가상 신청 한 건을 실제 처리하고 Chrome 화면을 촬영했다. 별도 시안·생성 이미지·브라우저 가상 로그인으로 만든 흐름이 아니다.

## 바로 확인하기

- 로그인 없이 보는 스크린샷 흐름: http://127.0.0.1:8098/process-flow/
- 실제 로그인: http://127.0.0.1:8087/login
- 이 신청의 진행 현황: http://127.0.0.1:8087/applications/47 (신청자 로그인 필요)
- 접수번호: `SUP-00000047`, 사례: 가상달빛식당 / 디지털 매장 전환

로컬 개발 초기 계정 `applicant`의 로그인 성공을 확인했다. 계정 설정은 `LocalSeed`와 12번 실행 안내를 따른다. 실제 운영 계정으로 사용하거나 운영 데이터를 이 체험에 넣지 않는다.

## 검증 경계

사업자등록증은 `digital` 가상 문서 PNG를 실제 업로드했다. 문자 인식은 `PP-OCRv5_mobile_det+korean_PP-OCRv5_mobile_rec`, 화면에 표시된 처리 시간은 10,675ms이며 이번 문서에서 상호·번호·대표자·개업일 네 값이 일치했다. 샘플 고정 응답이 아니다. NIM·OpenRouter 등 외부 AI는 비활성화했으며 호출하지 않았다. 이 한 건의 성공을 전체 문서 인식률로 일반화하지 않는다.

최초 견적서 v1에서 보완 견적서 v2로 교체했다. 보완본은 금액·설치·초기 설정·교육 내용을 재확인한 개별 서식 견적서이며 총액은 동일하다. 사업자등록증 v1과 최초 제출본은 유지했고 재제출에서 제출본 2를 생성했다. 최종 확정은 가상 사례 검토 결과로 실제 기관 선정·지원금 지급이 아니다.

마지막 결과 확정 확인창의 브라우저 연결 문제는 새 탭에서 확인창과 클릭을 함께 처리해 복구했다. 결과 확정과 신청자 최종 조회까지 완료했으며 대기 상태가 아니다. 로컬 DB에 테스트 신청·서류·OCR·처리 이력이 실제 저장됐다. DB 없는 공개 체험 모드는 이번에 구현하지 않았다.

## 파일과 재생성

- 실제 원본 스크린샷 22장과 단계 기록: `output/process-flow/`
- 원본 JPEG 형식이며 화면 내용을 합성·수정하지 않았다.
- 정적 흐름 페이지: `output/visual-direction/process-flow/`
- 페이지 생성: `python3 scripts/build-process-flow-gallery.py`

촬영 기록은 생성 산출물로 Git에서 제외한다. 새 체크아웃에서는 같은 업무 흐름을 다시 실행해 촬영해야 하며 갤러리 생성기만으로 새 실행 증거를 만들 수 없다. 서비스 코드·권한·DB 스키마는 이번 촬영에서 변경하지 않았다. 당시에는 커밋·푸시를 수행하지 않았다.
