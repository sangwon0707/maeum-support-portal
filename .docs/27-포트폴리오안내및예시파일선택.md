# 포트폴리오 안내와 파일 선택 모달

갱신일: 2026-10-26. 초기 첨부 모달·진행 연출 검증은 [이전 기록](archive/27-previous.md)에 보존한다.

## 현재 동작

공고에서 작성 문서 업로드를 누르면 운영체제 파일 탐색기 형태의 웹 모달을 연다. 실제 OS 창을 흉내 낸 별도 프로그램이 아니라 서비스의 HTML 모달이다. 사업별 가상 스캔 PDF와 미리보기를 제공하고 직접 파일 선택도 지원한다. 선택 파일 바이트를 실제 multipart 요청으로 서버에 저장한다.

공개 작성 문서 흐름은 PDF 한 묶음 선택이며 서버가 페이지·서류 경계를 나눈다. 기존 직접 작성의 사업자등록증·견적서 이미지 첨부와 구분한다. 모달을 열거나 취소하는 것만으로 신청·검토를 시작하지 않는다.

업로드 완료 후 원본 확인 화면에서 UPLOADED 상태를 유지한다. 사용자가 검토 방식을 선택하고 ‘문서 검토 요청’을 눌러야 처리한다. 로딩 표시와 퍼센트는 요청 후 나타나며, 검토 전에는 자동 인식하지 않는다.

## 안내·접근성

포트폴리오 고지는 최상단에 고정한다. 안내 켜기·끄기와 프로젝트 소개도 이 영역에 둔다. 다음 조작 대상으로 향하는 화살표와 강조 테두리는 실제 콘텐츠·버튼을 가리지 않게 배치한다. 별도 설명 말풍선을 여러 곳에 띄우지 않는다. 안내 상태와 서버 인증·업무 권한은 독립적이다.

모달의 닫기·취소·ESC·포커스 복원, 파일 선택·미리보기·오류 처리는 현재 스크립트와 서버 검증을 따른다. 파일을 첨부한 것처럼 보이기만 하는 고정 화면으로 대체하지 않는다.

## 검토 방식

OCR 검토 데모는 실제 생성해 저장한 결과를 불러오며 새 OCR·LLM을 실행하지 않는다. OCR 실제 검토는 새 서버 처리를 수행하고 처리 시간·외부 AI 텍스트 전송 안내를 확인한다. 두 방식은 같은 결과 검토 화면을 사용한다. 진행률은 승인·선정 결과를 뜻하지 않는다.

현재 범위·검증은 [29번](29-문서기반신청구현계획.md), [32번](32-LLM문서해석연동.md), [33번](33-PDFBox전환및회귀검증.md)을 따른다. 실제 로그인 성공 후에는 홈으로 이동한다.

## 역할별 진행 안내와 공통 확인 모달

로그인 전에는 사용자 테스트 계정 버튼에 금색, 관리자 테스트 계정 버튼에 핑크색 테두리와 화살표를 표시한다. 계정을 선택하면 안내 하나만 로그인·공개 계정 확인으로 이동한다. 관리자는 로그인한 실제 역할을 기준으로 접수 검토 → 미처리 접수 상세 → 검토 시작 → 결과 선택 → 사유 → 검토 확인 → 결과 확정 → 최종 확인 순서로 핑크색 안내를 받는다. 보완 사유를 직접 입력하면 보완 요청 버튼을 안내하고, 보완 대기·확정 이후에는 사용자 계정에서 상태를 확인하도록 로그아웃을 안내한다. 처리할 접수가 없으면 신청자 제출이 필요하며 가짜 접수를 자동 생성하지 않는다.

관리자의 다음 조작 대상이 화면 밖이면 대상이 바뀔 때만 화면 안으로 이동한다. 사용자가 다시 스크롤하는 것을 강제로 막지 않는다. 기존 최상단 안내 스위치와 움직임 줄이기 설정을 유지하며 설명 말풍선은 추가하지 않는다. 안내 색상은 브라우저 보조 표현이며 서버 권한이나 업무 상태를 바꾸지 않는다.

브라우저 기본 confirm을 사용하던 결과 확정·신청 예시 정보 불러오기·OCR 확인값 반영을 공통 dialog로 통일했다. 제목과 실제 변경 설명을 표시하며 결과 확정은 선택한 결과·사유도 함께 보여준다. 취소·ESC·닫기는 제출하지 않고 원래 버튼으로 포커스를 돌린다. 확인은 원래 submitter와 requestSubmit을 사용해 브라우저 입력 검증·CSRF·서버 경로를 유지한다. 중복 제출을 막고 뒤로가기 복원 시 다시 확인한다.

관리자 결과 확정은 사유 자동 입력 버튼으로 선택 결과에 맞는 문구를 채울 수 있다. 자동 문구는 검토 내용에 맞게 수정한다. 선정/미선정 변경은 직접 수정한 사유를 보존한다. 핑크색 안내는 빈 사유의 자동 입력 버튼과 검토 확인으로 이어지며 사유 입력만으로 결과를 확정하지 않는다.
