# 오라클 무료 서버 배포

작성일: 2026-10-26

## 대상과 배치

기존 서비스에서 사용하던 Ubuntu 24.04, VM.Standard.E2.1.Micro 서버에 마음이음을 별도 Docker Compose 프로젝트로 배치한다. 메모리 약 1GB, x86_64, 기존 부트 디스크 할당 47GB이며 서버 파일시스템 약 45GiB 중 점검 당시 약 36GiB가 비어 있었다. 디스크 증설은 수행하지 않았다. 기존 2GiB 스왑에 2GiB 파일을 추가해 총 4GiB로 구성한다. 스왑은 물리 RAM을 대체하는 성능을 보장하지 않는다.

기존 프로젝트 구성과 Caddyfile은 서버의 root 전용 백업 디렉터리에 보존한다. 기존 컨테이너는 삭제하지 않고 정지하며 원래 재시작 정책을 기록한 뒤 자동 시작을 해제한다. 기존 이미지와 공급자 키 파일도 보존한다. 새 DB·파일·OCR 모델 볼륨은 기존 프로젝트와 공유하지 않는다. 원격 인증키 내용과 기존 서비스 비밀 설정은 이 저장소에 기록하지 않는다.

새 배포 경로는 /opt/maeum이다. 로컬에서 검증한 WAR와 OCR 코드·요구 패키지·배포 설정만 전송한다. 프로젝트 전체, 로컬 DB, 이전 참고 프로젝트, 로컬 AI 키나 SSH 키는 이미지에 넣지 않는다. 새 DB 비밀번호와 OCR 내부 토큰은 무작위 생성 후 Git 제외 환경 파일로 전송한다. .env는 600 권한으로 보관한다. 초기 배포에서는 외부 생성형 AI를 비활성화했다. PDFBox 후속 배포에서는 OpenRouter의 Gemma 4를 사용하도록 변경하며 키는 비공개 서버 환경 파일에만 둔다. OCR 검토 데모는 외부 호출을 하지 않고, 실제 검토는 확인 후 추출 문구를 전송한다.

## 자원 제한

설정 원본은 deploy/oracle/compose.yml과 Dockerfile이다.

- Java: 힙 최대 192MiB, 메타스페이스 최대 160MiB, Serial GC, 인식 CPU 수 1개.
- MariaDB: InnoDB 버퍼 48MiB, 최대 연결 20개, Performance Schema 비활성화. 앱 DB 풀은 기존 8개를 유지한다.
- OCR: PaddleOCR CPU 스레드 1개, BLAS·OMP 스레드 1개. 실제 인식은 한 건씩 처리한다.
- 저사양 서버의 통합 PDF 인식 대기 상한은 900초다. 기본 로컬 설정은 300초를 유지한다. 실패를 고정 결과로 대체하지 않는다.
- Docker stdout 로그는 서비스별 10MiB × 3개로 순환한다. Tomcat 접근 로그는 7일 보관 후 정리한다.
- DB·OCR은 호스트 공개 포트를 열지 않는다. Java는 127.0.0.1:8088에 연결하고 기존 호스트 Caddy가 HTTPS를 처리한다.

메모리·스왑 제한은 프로세스를 작은 서버에서 시험하기 위한 설정이다. 실제 OCR 지연, OOM 여부, 메모리·스왑·디스크 사용량을 측정하기 전 안정 운영 가능하다고 표현하지 않는다.

## 주소와 HTTPS

사용자가 maeum.sangwonlee.dev의 Cloudflare 연결을 승인했다. 기존 sangwonlee.dev 존에 해당 호스트 A 레코드만 추가하고 Cloudflare 프록시를 사용한다. 다른 사이트의 DNS와 존 전체 SSL 설정은 변경하지 않는다. 기존 존 SSL 모드는 Full이었다. Caddy가 새 호스트의 공인 인증서를 발급하고 HTTP를 HTTPS로 리다이렉트한다. Tomcat RemoteIpValve로 프록시의 HTTPS 정보를 반영하여 로그인 리다이렉트와 세션 쿠키가 올바른 스킴을 사용하도록 한다.

Oracle 호스팅과 접속 기록, Cloudflare 프록시의 실제 처리 범위를 개인정보 처리방침에 조건부로 표시한다. 실제 공개 문의처는 서버 환경변수로만 주입한다.

## 확인 범위

준비와 실제 공개 서비스 검증은 구분한다. 이미지 빌드·컨테이너 healthy만으로 배포 완료라고 하지 않는다. 공인 HTTPS, 정적 이미지, 로그인 안내 확인과 홈 이동, PDF 업로드 후 UPLOADED 유지, 사용자 검토 요청 뒤 실제 OCR, 결과 화면·파일 접근 및 동일 문서 재사용을 확인한다. Git 작업과 운영 검증은 별도로 관리한다.

## Fail2ban SSH 보호 — 2026-10-26 추가

Oracle Ubuntu 호스트에 배포판 패키지 `fail2ban 1.0.2-3ubuntu0.1`을 설치했다. 기존 SSH 키 인증·비밀번호 인증 비활성 설정은 유지했다. 컨테이너가 아닌 호스트에서 systemd journal을 감시한다.

- 설정: `/etc/fail2ban/jail.d/maeum-sshd.local`
- 저장소 설정 원본: `deploy/oracle/fail2ban-sshd.local`
- SSH jail: systemd backend, iptables-multiport action
- 정책: 10분 내 실패 5회, 1시간 차단
- 상태: active·enabled, `fail2ban-client ping` pong, sshd jail 활성 확인
- 검증: 문서용 예약 주소 `198.51.100.23`을 수동 차단해 `f2b-sshd` REJECT 규칙 생성 확인 후 즉시 해제했다. 테스트 차단이 남지 않음을 확인했다.
- 설치 후 별도 SSH 접속 성공, 앱 내부 `/login` HTTP 200, 공개 도메인 HTTPS `/login` HTTP 200 확인

초기 재시작 직후 클라이언트가 소켓 준비 전 실행되어 실패했으나, 별도 접속에서 서비스·소켓·jail을 다시 확인해 정상 동작을 검증했다. 실제 공격 트래픽으로 실패 횟수 임계값을 시험한 것은 아니며, jail 설정값과 방화벽 액션을 각각 검증했다. 전체 보안 감사 완료를 뜻하지 않는다.

### 후속 상태 확인

2026-10-26 PDFBox 교체 작업 중 서버에 별도 접속해 Fail2ban active·enabled·pong과 sshd 정책 5회/600초/3600초를 다시 확인했다. 공개 HTTPS `/login`은 HTTP 200이었다. 이 재확인 시점에는 PDFBox 코드 변경이 로컬 검증 상태였다. 이후 원격 이미지 검증과 운영 교체는 아래 후속 기록을 따른다.

## PDFBox·Gemma 4 운영 반영 — 2026-10-26

검증한 `maeum-ocr:pdfbox-review-20261026` 이미지와 새 앱 WAR를 기존 Compose에 반영했다. 앱 수정 이미지 ID는 `57daf2117365`, PDFBox OCR 이미지 ID는 `e90714a71918`이다. DB·파일·모델 볼륨은 유지했다. Flyway는 V12까지 정상 적용했다. 만료 인덱스는 긴급 수정 과정에서 먼저 생성되어 V12의 IF NOT EXISTS에서 이미 존재한다는 경고가 나왔지만 마이그레이션은 성공했다.

외부 AI 공급자는 OpenRouter, 모델은 `google/gemma-4-26b-a4b-it`다. 키는 서버 .env(600)에만 주입하고 이미지·WAR에는 넣지 않는다. 호출 예산 상태는 OCR 모델 볼륨 안의 별도 SQLite 경로에 보관해 재시작 후에도 유지한다. 기본 6 RPM·동시 1건을 적용하며 다른 서버·프로젝트의 한도까지 합산하는 중앙 제한기는 아니다.

공개 홈·로그인·공고·이용약관·개인정보·프로젝트 소개가 HTTP 200, `/demo`가 404임을 확인했다. 업로드 후 UPLOADED가 유지됐고 검토 데모는 READY, 결과 이미지 접근은 200이었다. 실제 검토 전송 안내를 기존 확인 체크와 개인정보 처리방침에 반영했다.

첫 데모의 DB 교착 및 수정, 빌드와 실제 검토를 동시에 실행해 발생한 응답 지연은 33번 문서에 기록한다. 이미지 생성·컨테이너 재시작을 실제 처리와 겹치지 않게 해야 한다. 배포 중 앱 재시작으로 일시적인 접속 중단이 있었다. 앱·OCR 이전 이미지를 별도 태그로, 이전 WAR·Compose·환경 파일은 서버의 비공개 롤백 폴더에 보존했다. 디스크 증설·커밋·푸시는 하지 않았다.

최종 공개 실제 검토도 통과했다. 작성 PDF 업로드 후 요청 전 UPLOADED 유지, 확인 후 LIVE 실행, READY와 결과 PNG 200을 확인했다. 전체 103.29초, AI 상태 SUCCEEDED·원문 검증 20건이었다. 텍스트 PDF 처리 사례이며 전체 스캔 처리 시간으로 표시하지 않는다. 앞선 검토 데모 통과와 함께 새 운영 버전의 두 흐름을 확인했다. 상세는 33번 문서를 따른다.

## 저장소 자동 실행 정책

2026-10-26 사용자 요청으로 GitHub Actions를 저장소 설정에서 비활성화했다. 당시 실행 중인 워크플로와 등록 웹훅은 없었다. 이번 브랜치 푸시·PR은 운영 배포와 분리하며, 오라클 배포는 별도 명시적 작업으로 수행한다.

## 최종 로컬 정비와 기존 운영 버전의 구분

PDFBox·OpenRouter 기능 버전은 위 기록대로 운영에 반영했다. 이후 정부 캡처·미사용 상징 제거, 라이선스 원문 동봉, 공개 출처 이동, 문서 현행화는 로컬 소스 정비이며 서버에 다시 전체 배포하지 않았다. 새 저장소 생성은 이 문서 점검과 별도 작업이다. 고지·정적 파일만 서버에 반영하는 경우에도 실제 반영 결과를 따로 기록한다.

## 저장소 재생성과 정적 고지 반영 — 2026-10-26

기존 저장소는 사용자가 삭제했고, 같은 이름 `sangwon0707/maeum-support-portal`로 비공개 저장소를 새로 만들었다. 로컬 Git도 초기화했으며 새 main은 첫 커밋 하나로 시작한다. 작성자 이메일은 GitHub noreply를 사용하고 Actions는 비활성화했다. 이전 브랜치·PR·커밋을 새 저장소에 가져오지 않았다.

폰트 OFL·저작권, Swiper MIT, KRDS 출처 안내·CSS, 통합 고지를 현재 앱 컨테이너에 반영하고 미사용 정부 파비콘 4개·공식 상징 SVG 3개를 제거했다. 공개 `/login`과 3개 라이선스 파일은 HTTP 200이었다. 앱·DB·OCR 컨테이너가 계속 healthy이며 재시작하지 않았음을 확인했다.

이번 작업은 실행 중 컨테이너의 정적 파일 갱신이다. 기존 앱 이미지 자체를 새로 빌드한 것은 아니므로 이전 이미지로 컨테이너를 재생성할 때 이 갱신이 자동으로 유지된다고 가정하지 않는다. 다음 이미지 빌드에서는 정비된 소스·고지 포함 설정으로 패키징해야 한다. 기존 DB와 업로드 자료는 보존했다.
