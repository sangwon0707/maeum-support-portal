> 보존 기록: 본문의 예정·미구현·검토 대기·배포 상태는 작성 당시의 기록이다. 현재 기능과 운영 상태는 원래 번호 문서 및 15·31~33번을 따른다.

## 2. 공통 화면 규칙

- 공개 메뉴: 지원사업, 예시 체험, 로그인. 신청자 메뉴: 나의 신청. 담당자: 담당 업무·통계. 관리자: 공고·배정·감사 이력.
- 제목·현재 위치·상태·주요 행동을 일관되게 배치. 목록은 검색 조건·전체 수·페이지 크기(20)를 표시한다.
- 서버 검증 오류는 상단 요약과 필드 옆 메시지로 함께 제공하고 첫 오류로 이동한다.
- 처리 중에는 중복 행동을 막고 완료/실패를 텍스트로 알린다. 저장되지 않은 변경을 가진 화면을 떠날 때 확인한다.
- 실패 시 입력값 보존. 401 재로그인, 403 접근 불가, 409 최신 정보 재조회, 422 항목 수정, 5xx 재시도 안내.
- 와이어프레임은 흑백 구조 검토용이다. KRDS 리소스·디자인 토큰·공식 컴포넌트 적용 완료를 의미하지 않는다.

## 3. SC-04 신청 입력 상세

| 필드 | 필수/타입 | 검증·안내 |
|---|---|---|
| 상호 | 필수 문자열 100자 | 공백만 입력 불가 |
| 사업자등록번호 | 필수 숫자 10자리 | 표시 시 하이픈 가능, 저장은 숫자. 실재 여부 검증 아님 |
| 대표자 | 필수 문자열 50자 | OCR 대조 대상 |
| 개업일 | 필수 날짜 | 미래 날짜 불가 |
| 연락처 | 필수 문자열 20자 | 숫자·하이픈 허용, 형식 검증 |
| 개선 계획 | 필수 문자열 2,000자 | 사용자가 입력한 HTML은 텍스트로 출력 |
| 신청금액 | 필수 정수 | 1~10,000,000원 |

임시저장은 필수 항목 미완성을 허용하되 형식·길이·권한은 검사한다. 다음 이동은 초안 저장 후 실행한다.

## 4. SC-06 OCR 대조 상세

행별로 항목명·OCR 추출값·신청값·최종 확인값·불일치 상태를 표시한다. SAMPLE/LIVE 배지를 항상 노출한다. 상호·번호·대표·개업일 4항목. 대기/처리/완료/실패를 구분하며 실패 시 직접 입력으로 진행 가능하다. 다른 서류 버전의 결과는 사용하지 않는다. 확인 저장 전에는 최종값 확정으로 표시하지 않는다.

## 5. SC-09 보완 상세

담당자의 요청 사유·마감 시각·허용 변경 항목을 상단 고정 정보로 제공한다. 요청 항목만 편집 가능하고 이전 제출 내용과 새 값을 비교한다. 보완 답변은 2,000자, 필수다. 재제출 후 새 revision을 생성하고 이전 제출본을 보존한다.

## 6. SC-11 검토 상세

좌측 신청 정보·원본, 우측 검토 체크 항목·추출 비교·처리 이력. 검토 시작은 SUBMITTED에서, 보완·확정은 UNDER_REVIEW에서만 활성화한다. 보완은 항목·사유(1,000자)·미래 기한 필수. 결과 확정은 선정/미선정 선택·사유(1,000자)·최종 확인이 필요하다. 금액 지급 동작은 없다.

## 7. 목록·통계와 관리자

SC-10: 검색 조건은 상태·제출 기간·상호·접수번호, 담당자는 본인 배정만 조회한다. SC-12: 담당자는 본인 배정, 관리자는 전체 운영 공간을 조회한다. 상태 합계와 목록 수의 기준(현재 상태·동일 조건)을 동일하게 유지한다. 보완 기한 초과는 NEEDS_SUPPLEMENT이며 due_at ≤ 기준 시각인 건이다.

SC-13: 공고 제목 200자, 본문 10,000자, 접수 시작<종료, 한도 양수, 필수 서류 코드 목록. 배정 대상은 STAFF 계정, 이관 사유 1,000자. 접수 시작 이후 기간·서류 규칙 수정은 차단한다. SC-14는 상태 변경/배정/파일 열람을 조건 조회하며 문서 원문·토큰은 표시하지 않는다.

## 실제 OCR·AI 보조 확장 — 2026-10-23

최신 화면·V3 스키마·공급자 계약·실행 결과는 [OCR 및 AI 연동 보고서](../19-OCR및AI연동보고서.md)를 따른다. 앞 절의 초기 설계·기존 검증 기록과 구분한다.

## PDFBox 전환 관련 화면 — 2026-10-26

업로드 모달·검토 요청 전 원본 확인·신청 내용·서류 분할·사진/표·확인/제출의 경로와 데이터 계약은 유지한다. PDFBox가 생성한 실제 미리보기·분할 PDF·사진을 기존 검토 화면에서 조회한다. 프로젝트 소개와 README의 기술 표기를 Apache PDFBox로 갱신했다. AI 해석 결과는 접을 수 있는 표로 제시하고 원문 근거·분류 불일치를 확인한다. 문서 전환 검증은 33번 문서를 따른다.
