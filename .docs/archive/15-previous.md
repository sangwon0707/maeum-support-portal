## 1. 기존 실행 검증 기록

아래 실행 주소·해시·테스트·HTTP·SQL·브라우저 수치는 당시 기록이다. 이번 문서 갱신에서는 서비스 재빌드·재시작·Java/HTTP 테스트를 재실행하지 않았다. 현재 실행 여부를 보장하는 실시간 상태표가 아니다.

실행 주소: http://127.0.0.1:8088/ . Linux Tomcat 10.1.48 / Java 21 컨테이너와 실제 MariaDB 11.4.13을 사용한다. 원격·운영 공급자에 공개 배포한 상태는 아니다. 개발용 내장 Tomcat(8087)은 검증 후 종료하고 Linux 실행본을 남겼다.

빌드한 WAR와 실행 컨테이너의 ROOT.war SHA-256이 일치한다.

## 5. SQL 측정

가상 신청 10,000건, 담당 배정 5,000건. 동시 작업 10개, 예열 후 200회 표본. 목록 20건 조회와 상태 집계의 한 쌍을 측정했다.

- p95: 110ms
- 최대: 174ms
- 비교: 정렬 인덱스 제외 시 Using filesort, 추가 인덱스 사용 시 ix_application_status_sort / Using index.
- 인덱스 제외·사용 조회 결과와 집계 수가 일치함을 검사했다.

로컬 Docker MariaDB + JDBC/MyBatis 측정이며 전체 HTTP 응답·고객 운영 성능을 뜻하지 않는다. 원자료: output/sql-performance.json. EXPLAIN 예상 rows는 통계 추정값이며 실제 행 수로 해석하지 않는다.

## 6. 브라우저 검토

Playwright로 실제 Linux 앱에서 예시 선택 → 신청 저장 → 서류 확인 → OCR 확인값 저장 → 제출 → 담당자 전환 → 검토 시작을 수행했다. 신청·첨부·OCR·최종 확인·진행·업무 목록·검토의 7개 화면을 1440/390px에서 총 14회 점검했고 페이지 가로 넘침이 없었다. 역할·결과 확정은 별도 HTTP 점검에서도 확인했다. 관리자 로그인과 관리 화면을 열었다.

메인·공고 상세·예시 체험은 1440/900/390px에서 추가 점검했다. 대표 PC OCR 화면과 모바일 검토 화면은 이미지를 직접 열어 육안 확인했다. 스크린샷은 output/playwright/final-*.png에 보관한다. 클릭 영역·공식 CSS의 이미지 상대 경로를 수정 후 실제 입력 선택·체크 동작을 확인했다.

이는 전체 접근성 인증·실기기 검증·모든 오류 변형의 브라우저 완전 탐색을 뜻하지 않는다. 이전 와이어프레임 점검 결과와 제품 검증 결과를 구분한다.

## 7. 남은 범위와 제한

| 항목 | 상태 |
|---|---|
| 실제 OCR 엔진·비용·30초 외부 호출 timeout | P2 미연동. 샘플 고정 응답만 제공 |
| Oracle 호환성 | 미검증. MariaDB만 검증 |
| 공고별 필수 서류 자유 편집 | 1차 사업 규칙에 맞춰 사업자등록증·견적서로 고정 |
| 만료 데모 물리 삭제 | 접근 차단은 구현. DB·파일 자동 정리는 후속 |
| 실제 백업·복원 / 원격 운영 배포 | 미검증 |
| 종합 접근성·모바일 실제 기기 | 브라우저 크기·기본 조작 점검만 수행 |
| 실제 개인정보·정부 인증·지급 | 범위 제외. 가상 자료 전용 |

설계 초안의 모든 비기능 수용 항목이 완료된 것으로 표시하지 않는다. 현재 실행 가능한 업무와 확인한 증거를 위 범위로 한정한다.

## 8. 환경 준비 기록

개발용 Java 21은 .tools에 확보했다. Docker Desktop을 실행하고 프로젝트 전용 DB·앱 컨테이너와 볼륨을 생성했다. 환경 준비 중 Homebrew MariaDB 11.4 패키지도 설치했으나 실제 검증은 Docker DB를 사용하며 Homebrew DB 서비스는 실행하지 않았다. 프로젝트 소스·실행 자료·DB는 다른 프로젝트와 구분했다.

## 9. 예시 자료 제작·검증 갱신

가상상점 최종 7쪽, 그 PDF를 이미지로 합성한 7쪽, 다른 입력값의 가상문구점 7쪽 PNG를 제작했다. 모든 페이지 배치를 확인했고 이미지형 PDF의 텍스트 층 없음·페이지당 이미지 1개와 합계를 검사했다. 파일·정답·재생성 절차는 17번 문서 참조. 실제 OCR은 실행하지 않았다.

자동 체험은 여전히 기존 FixtureImages·SampleOcrProvider를 사용한다. 새 자료가 포함된 WAR를 배포하거나 체험·PDF 업로드에 연결한 증거는 없다. 위 WAR 해시는 새 문서 파일을 포함한 빌드의 해시가 아니다.

## 10. 최초 커밋 전 재검증 — 2026-10-23

`./scripts/format.sh --check` 통과. `./scripts/test.sh`를 실제 MariaDB 테스트 스키마에서 다시 실행해 17개 성공(실패·오류·건너뜀 0), WAR 패키징 성공을 확인했다. HTTP·브라우저 점검과 실행 컨테이너 배포는 이번에 재수행하지 않았다. 앞 절의 기존 WAR 해시·SQL 측정치는 과거 기록으로 유지한다.

커밋 대상의 비밀키 패턴·제외 폴더 혼입을 점검했다. 글꼴 원본 OFL.txt의 기존 줄 끝 공백은 라이선스 원문 보존을 위해 수정하지 않았고, 나머지 스테이징 파일의 공백 검사는 통과했다.

Java/MariaDB 66개, PDFBox 모듈 3개, Python API 33개 통과. 실제 스캔 PDF 6쪽의 PDFBox → PaddleOCR → OpenRouter 처리와 신청서 반영·최종 제출·담당자 배정 전후 원본 접근을 검증했다. PyMuPDF 패키지를 제거한 상태에서 테스트했다. 상세 입력·출력·연관 페이지와 Docker 검증 한계는 33번 문서에 기록한다.

## 오라클 PDFBox 이미지 검증 — 2026-10-26

Oracle linux/amd64 이미지 빌드와 실제 API 검증을 통과했다. PDFBox 3.0.8 상태·미인증 401·텍스트 PDF 6쪽·사진 1개·2쪽 분할·OpenRouter 원문 검증 23건·스캔 1쪽 PaddleOCR 57줄을 확인했다. 원격 앱 전체 업무 E2E와 별도 범위다. 측정값은 [33번 문서](../33-PDFBox전환및회귀검증.md)에 기록했다.

공개 사이트 첫 데모 검증은 DB 교착으로 실패했다. 이를 숨기거나 통과 횟수에 넣지 않는다. 실제 작업 만료 수거 전용 인덱스와 실행 모드 조건을 추가한 뒤, 별도 실제 MariaDB에서 데모 행 잠금과 만료 수거를 동시에 실행해 상태 보존을 확인했다. 자세한 실패 원인과 재검증은 33번 문서에 기록한다.

최종 이미지 반영 후 공개 실제 검토 작업 6번은 103.29초에 READY로 완료됐다. AI SUCCEEDED·원문 검증 20건이 DB에 저장됐고 결과 이미지 조회는 200이었다. 공개 업로드 대기·검토 요청·결과 확인을 통과했다. 이번 공개 확인에서 최종 제출·담당자 배정까지 새로 실행한 것은 아니며, 그 범위는 앞선 로컬 회귀 결과를 따른다.
