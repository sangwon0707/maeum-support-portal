> 보존 기록: 본문의 예정·미구현·검토 대기·배포 상태는 작성 당시의 기록이다. 현재 기능과 운영 상태는 원래 번호 문서 및 15·31~33번을 따른다.


이 문서는 작성 당시 상태를 보존한 기록이다. 현재 설명은 원래 번호의 문서를 따른다.

# 포트폴리오 안내와 예시 파일 선택

## 목적

방문자가 개인 서류를 준비하지 않아도 신청·첨부 과정을 확인할 수 있도록 한다. 파일 탐색기를 닮은 웹 모달에서 공고에 맞는 가상 문서를 선택한다. 실제 운영체제 창을 열지 않으며, 직접 업로드는 별도 펼침 영역에서 유지한다.

## 동작

- 왼쪽은 사업자등록증·견적서 폴더, 가운데는 해당 공고의 예시 파일, 오른쪽은 원본 미리보기다.
- 클릭하면 선택하고, ‘선택해서 첨부’ 또는 더블클릭으로 첨부한다.
- 이미지 로딩 완료 후 첨부가 가능하며, 처리 중 중복 요청과 닫기를 막는다. 실패하면 오류를 표시하고 재시도를 허용한다.
- ESC·취소·닫기 후 원래 버튼으로 포커스를 복원한다.
- 파일 바이트를 가져와 기존 multipart 업로드에 보낸다. 기존 CSRF·소유권·파일 검증·트랜잭션을 그대로 거친다. 첨부된 것처럼 화면만 바꾸지 않는다.
- 보완 상태에서는 서버 Service가 허용한 서류 종류와 기한에 맞춰 선택 버튼을 노출한다. 저장 시 서버에서 다시 검증한다.

## 포트폴리오 안내

켜기·끄기는 기존 최상단 포트폴리오 고지 줄에 통합하며 스크롤해도 상단에 고정한다. 별도 상단 안내 영역은 두지 않는다. 설명 말풍선 없이 다음 조작 대상 바로 옆의 화살표 하나로 안내한다. 입력·첨부 상태에 따라 다음 대상으로 이동한다. 화면 밖 대상에는 최상단의 위치 이동 버튼을 제공한다. 안내 켜짐 여부만 sessionStorage에 저장하며 인증 정보는 저장하지 않는다. 안내를 꺼도 서비스 기능은 동일하다.

이미 제출한 신청서를 다시 시작하거나 수정 URL로 접근하면 현황 화면으로 이동한다. 상태 변경 권한은 기존 Service 검증을 유지한다.

## 검증 기록 — 2026-10-25

- 최초 Maven verify: 통합·정책 테스트 40개 통과. 타인 접근·보완 교체 범위 검증 포함. 이후 제출 후 수정 화면 연결 회귀 검증을 추가했다. 마지막 전체 재실행은 디스크 공간 부족과 로컬 DB 연결 지연으로 완료하지 못했으므로 추가 변경까지 전체 통과했다고 해석하지 않는다.
- 로컬 Chrome: 에너지 절감 사업 신청 48번에서 예시 입력 → 저장 → 사업자등록증 선택·첨부 → 견적서 더블클릭 첨부 확인. 서류 104·105가 각각 버전 1로 저장됐다.
- 데스크톱·390px 모바일에서 모달과 미리보기 확인. 가로 넘침 없음, 첨부 버튼 화면 내 노출, 안내 끄기·ESC·포커스 복원 확인.
- 화면 증거: `output/portfolio-guide/예시파일선택-데스크톱.jpg`, `예시파일선택-모바일.jpg`.
- 이번 검증은 로컬 UI·Java 업로드·DB 저장 근거다. 실제 OCR 공급자 호출·배포 검증으로 해석하지 않는다. 일반 신청자 계정은 실제 로컬 DB에 저장하며 공개 방문자의 무저장 모드는 별도 과제다.

커밋·푸시는 사용자 검토 후 진행한다.


## OCR 처리 연출

실제 작업 상태가 RUNNING일 때 원본에 스캔 빛을 표시하고 완료 후 네 항목을 차례로 정리한다. 결과 좌표가 있는 경우에만 원본 영역을 강조한다. 비교 결과와 사용자 확인은 별도로 표시하며 확인 전 신청값을 바꾸지 않는다. 화면 검토 시안과 실제 OCR 호출 근거는 구분한다. ADR-033 참조.
